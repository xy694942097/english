# 长文快速原位编辑（2026-10-12）

## 问题与决定

原先点击「编辑本文」会让 TOAST UI Editor 把整篇 Markdown 转成所见即所得文档。约 338 KB 的 Better Call Saul 页面即使预加载脚本仍要约 3.4 秒；后来加入的“先选小节”虽然降低转换量，却把内部性能问题变成用户操作负担。该流程已撤下。

现行主流程是：点击「编辑本文」立即让**已渲染的正文块**进入浏览器原位编辑，页面、导航和当前阅读位置保留。只在保存时将实际改过的块转回 Markdown，并用原源码中的块范围逐个替换；其他字节保持原样。复杂格式或源码范围无法充分定位时，回退到原来的全文编辑器。

## 数据边界

1. `marked.lexer` 的顶层 token 提供原始 `raw`，与同一次 `marked.parser` 输出的顶层节点逐个对齐；只有节点数量吻合时才标记源码起止位置。阅读页随后折叠章节，位置属性仍附着在标题、段落、引用、列表、表格与代码块上。
2. 点击编辑仅设置这些节点的 `contenteditable`。打开动作不加载 TOAST UI，也不重新解析整篇文档。工具栏用于少量常用行内格式。
3. 保存时只收集 HTML 与编辑前不同的块。普通块交给本地 TOAST UI 转回 Markdown；代码块保留原 fenced code 的语言标记。查看器为相对链接和图片生成的展示地址在序列化前还原为原始 Markdown 地址。
4. 多块修改按源码位置从后往前替换，最后通过 `/api/document` 提交整份结果。服务端仍用打开时的 SHA-256 阻止覆盖外部修改。取消编辑会丢弃浏览器 DOM 修改，不写磁盘。

## 边界与验证

- 此模式适合修改已有内容块；跨块拖选并合并段落、复杂表格重构与原始 HTML 不是本轮目标。用户可主动进入「高级格式」全文编辑器，源码覆盖低于 80% 时也自动回退。切换前未保存的快速修改须先保存或放弃。
- 所见即所得转回 Markdown 可能规范化**被改动的块**，不会规范化全篇。保存后仍可用 Git 检查和回退。
- 本机无预热浏览器中，短文章点击进入约 52 毫秒，Better Call Saul 长文约 128 毫秒；这些是交互延迟的实测样本，不是跨设备性能保证。
- 已验证短文与长文输入、单块保存且前后源码不变、相对 Markdown 链接保持、加粗工具栏、取消、目录与阅读回归。测试入口：`site/test_server.py`、`site/test_reader.cjs`。
