# English Book 产品设计复盘

日期：2026-09-15  
状态：当前阶段复盘，供下一轮收敛设计使用

## 一句话结论

现在的 English Book 已经有了教材、知识库、复习、录入、词典 API、查词页面和网页老师，但它还不好用。主要问题不是功能不够，而是产品主线不够清楚：它同时像一本书、一个词典、一个 Anki、一个导入工具、一个聊天老师和一个资料库，但用户打开后不知道此刻最应该做什么。

这不是某个按钮或页面的问题，而是设计阶段没有先把“学习行为链路”压实。我们过早把很多可能有用的能力都接了进来，导致系统能力在增长，学习体验却没有同步变清楚。

## 当前已经做出来的东西

### Book

Book 已经从单纯的 Markdown 阅读，发展成按专题组织的教材。当前主线包括：

- 熟词生义
- 整句词组
- 常用句型
- 特殊句子
- 单词专题

这条方向是对的，因为用户真正卡住的不是“单词量不够”，而是熟词、搭配、结构和语境义一起出现时，句子突然读不通。

### 学习记录与复习

系统已经有 SQLite 学习库，支持：

- 标记本次学习
- 理解 / 表达两种进度
- 到期复习
- 保存原答、自评、用时、提示程度
- 撤销学习事件
- 批量录入词、词组、句子、语法和表达

这个方向也对，因为成人学习不能只看“我看过了”，而要保留证据：当时怎么理解、是否独立完成、什么时候该复习。

### 词典与查词

已经合并了本地词典库，包含：

- 中文解释
- 英英解释
- 词根词缀
- 词形还原
- WordNet 义项
- 同义、反义、派生关系
- 词组
- 例句
- 联想辨析

并且已经提供 `/api/dictionary/lookup`、`/api/dictionary/search`、`/api/dictionary/stats`，也接入了网页查词页。正文里可以选中英文词查词，也可以从词典页回到原文。

这解决了“终端 curl 不好用”的问题，但还没有解决“查到了以后怎么学”的问题。

### 网页老师

网页老师能结合用户背景、当前章节和对话历史回答问题。这是核心优势，因为用户的真实问题往往不是“这个词什么意思”，而是：

- 为什么这个句子我拆不开？
- 这个熟词为什么不是我初中学的意思？
- 这个词组应该整体识别吗？
- 这句话如果从中文翻译成英文，怎么说更地道？

老师能力强，但目前它在页面里只是一个右侧聊天框，没有足够深地嵌入学习流程。

## 为什么现在不好用

### 1. 入口太多，但主任务不清楚

现在用户可以：

- 看专题课程
- 搜索知识书
- 查词典
- 看词表资料库
- 录入词句
- 做今日复习
- 和老师聊天
- 点章节里的知识点

这些功能单独看都有意义，但组合在一起会让页面变成工具箱。工具箱的问题是：它把选择成本交给了学习者。

成人学习需要自顶向下，但自顶向下不等于把所有工具摆出来。更好的首页应该回答一个问题：

> 我今天打开这个网站，应该先做哪一件事？

当前答案不够明确。

### 2. 知识组织和资料组织混在一起

Book、知识库、词典、词表资料库都在展示“英语知识”，但它们的角色不同：

- Book 是学习路线，应该少而精。
- 知识库是可复习对象，应该稳定、可追踪。
- 词典是查询资料，应该宽而全。
- 词表资料库是来源集合，应该服务导入和筛选。

现在这些边界在实现里基本有了，但在用户界面里不够明显。结果是用户会感觉“知识很多，但没有重点”。

尤其是词典接入后，这个问题会更明显。词典会返回大量义项、关系、词组和例句，但这些不等于学习内容。查词结果如果不经过教学筛选，就容易变成另一个信息噪音源。

### 3. 查词页解决了查不到，但没有解决读不懂

用户最开始的问题是 `resigned`：词认识，但句子看不懂。真正卡点在：

> resigned to the worst 是省略结构 + 固定搭配 + 情绪语义。

普通词典会告诉你 `resigned = 顺从的 / 已辞职的`，但不会自动告诉你这里是：

> as though he were resigned to the worst

所以词典页不能只是展示资料。它应该进一步回答：

- 这个词在当前句子里是哪一个义项？
- 是否有固定搭配？
- 后面的介词归谁管？
- 这句话应该怎么拆？
- 这个知识点是否值得加入复习？

当前查词页还停留在“资料查询”，没有变成“阅读诊断”。

### 4. 学习记录太靠后，不像自然动作

现在标记学习、复习、录入都已经能用，但学习动作和阅读动作之间还不够自然。

理想情况是：

1. 用户读到一句话卡住。
2. 选中词或句子。
3. 系统查词 / 查搭配 / 让老师解释。
4. 老师判断这是词义、搭配、句型、长难句还是翻译表达问题。
5. 用户一键保存为知识点。
6. 系统安排复习。

当前流程更像：

1. 用户读正文。
2. 发现不会。
3. 去查词典或问老师。
4. 如果想记录，还要再去录入或知识库。

中间有断点。断点越多，学习系统越容易沦为“做得很强，但用户懒得用”。

### 5. “老师”还没有成为产品的组织者

这个项目最大的优势其实不是词库，而是 GPT 老师能因材施教。用户已经明确说过：高考英语和六级成绩不低，但多年不用，听力暂缓，主要问题是词组、熟词生义和句子整体理解。

这意味着老师应该成为学习系统的核心调度者，而不是一个附属聊天框。

更好的形态是：

- 老师从当前阅读材料出发。
- 老师判断卡点类型。
- 老师从词典和 Book 里取资料。
- 老师给出精讲。
- 老师生成可复习的最小知识点。
- 用户确认后入库。

现在是页面围绕 Book 和工具组织，老师在旁边。下一版应该让老师成为“读懂这句话”的主流程入口。

## 用户真实需求重新表述

用户并不是要一个普通背单词网站。真实需求更像：

> 我想建立一个电脑端的个人英语学习系统。它要围绕我真实读不懂的地方工作，把词典、教材、复习、录入和 GPT 老师整合起来，帮助我从“认识很多词但句子不熟练”过渡到能稳定读懂、表达和迁移。

几个关键约束：

- 听力可以先不管。
- 不追求每天打卡式 App。
- 不用一上来铺满海量词条。
- 重视可理解输入、真实语境、时间积累。
- 成人学习要先方法论、自顶向下、实用导向。
- 已讲解不等于掌握，需要延迟复习和独立应用。
- 词典资料要丰富，但不能替代教学筛选。

## 下一版应该怎么收敛

### 第一优先级：把首页改成“今日学习台”

首页不应该先展示所有专题，而应该先给一个明确动作：

1. 继续上次阅读
2. 今日到期复习
3. 粘贴一句读不懂的英文
4. 查一个词

其中“粘贴一句读不懂的英文”应该是最重要的新入口。因为这最贴近用户的真实卡点。

专题课程仍然保留，但变成第二层。资料库、录入、词典都作为工具，不抢主线。

### 第二优先级：做“句子诊断”入口

输入一句英文，例如：

> Ron sighed as though resigned to the worst.

系统输出：

- 主干：Ron sighed
- 省略：as though he were resigned to the worst
- 关键搭配：be resigned to
- `to` 是介词
- 情绪：无奈接受，不是辞职
- 可保存知识点：be resigned to / as though + 省略 / resign 熟词生义

这比单纯查 `resigned` 更有学习价值。

### 第三优先级：查词结果要有“教学筛选层”

词典页应该分两层：

第一层：快速答案。

- 当前最可能义项
- 常见搭配
- 2 个最有用例句
- 一句中文解释

第二层：展开资料。

- 全部英英义项
- 词根词缀
- 同反义关系
- 更多例句
- 来源信息

现在页面更接近第二层。下一步要补第一层。

### 第四优先级：一键从查词/问答生成学习条目

查词或老师解释后，应该出现：

- 加入复习
- 保存为词组
- 保存为熟词生义
- 保存为句型
- 保存为长难句
- 保存为翻译表达

保存前给用户一个可编辑草稿。确认后进入知识库和复习计划。

这样录入功能就不再是孤立页面，而是自然嵌在阅读和问答之后。

### 第五优先级：Book 继续少而精

Book 不应该被词典规模带偏。词典可以 77 万词，Book 不需要 77 万章。

Book 的价值是把高频卡点组织成专题，例如：

- 熟词生义：resign / evidence / issue / appreciate / address
- 抽象名词搭配：gain traction / raise questions / pose a challenge
- 介词决定结构：to doing / from doing / in doing
- 小词结构：nothing but / anything but / all but
- 翻译表达：中文一句话的多种英文说法

每章只讲少量高价值点，讲透、练迁移。

```text
├── 今日复习
├── 粘贴一句读不懂的英文
└── 查一个词

学习主线：Book
├── 熟词生义
├── 整句词组
├── 常用句型
├── 特殊句子
├── 单词专题
└── 中文到英文表达

工具区
├── 词典
├── 知识库
├── 录入
└── 来源资料

老师
├── 解释当前句子
├── 判断卡点类型
├── 给新语境
├── 生成可复习知识点
└── 评阅用户回答
```

## 设计原则修订

### 原则 1：先读懂一句话，再扩展知识

不要从“我要学 indignant”开始，而是从“这句话里 indignant 为什么这么用”开始。词典服务句子，词组服务句子，语法也服务句子。

### 原则 2：资料和教学分层

词典资料可以多，教学页面必须少。默认展示最有用的内容，更多资料折叠。

### 原则 3：每个学习对象必须可复习

如果一个知识点不能形成复习任务，它就只是资料。可复习对象应该小而明确：

- 一个词在某个义项下的用法
- 一个固定搭配
- 一个句型结构
- 一个翻译表达
- 一个长句拆解方法

### 原则 4：老师不是聊天工具，而是学习流程的编排者

老师应该帮助用户把混乱输入变成结构化学习对象。用户给一句话，老师负责识别卡点、解释、生成练习、建议是否入库。

### 原则 5：Book 不追求大而全

大而全交给词典和资料库。Book 只负责高价值路径和反复出现的卡点。

## 下一步最值得做的一个功能

最值得做的不是继续下载更多词典，也不是继续加更多词条，而是做：

> 句子诊断页：输入一句英文，老师结合词典和已有 Book，拆出卡点，并允许一键保存为可复习知识点。

这个功能能把当前系统里的几块能力串起来：

- 阅读卡点
- 词典查询
- 老师讲解
- 知识点生成
- 入库
- 复习

如果这条链路顺了，English Book 才会从“工具集合”变成真正的个人英语学习系统。

## 下一轮明确不优先做什么

为了避免继续发散，下一轮先不优先做这些事：

- 不继续追求下载更多词典。当前词典已经足够支撑查词和辅助诊断，短板在筛选和使用。
- 不继续批量铺词表。更多词条会让系统更大，但不会自动让学习路径更清楚。
- 不把首页继续改成内容陈列页。首页应该是行动入口，不是目录墙。
- 不急着做公网部署。当前是个人电脑端学习工具，本地闭环先顺。
- 不急着做复杂统计图。统计只有在能指导下一步学习时才有价值。
- 不把每次老师回答自动写进 Book。老师回答可以生成候选，正式入库和编入教材仍需要用户确认。

下一轮只围绕一个目标做：

> 让用户输入或选中一句读不懂的英文，系统能完成诊断、讲解、保存和复习安排。

## 当前判断

这次设计不是失败，而是典型的探索期发散：我们把可能需要的基础设施搭了不少，但还没有把学习主路径压成一个简单动作。现在该停止横向加功能，转向纵向打磨一个闭环：

> 遇到一句读不懂的话 → 诊断 → 精讲 → 保存 → 复习 → 迁移使用。

下一轮所有功能都应该服务这条链路。不能服务这条链路的，先放到工具区或 backlog。
