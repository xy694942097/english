# 家族A排版样张 · 风格二：代码块主体（用户提议）

英语例句全部用 ``` 代码块呈现：等宽字体、视觉上像"代码/骨架"，与结构拆解风格统一。适合把英语句子当"待解析对象"看的学习方式。缺点：等宽字体阅读长句不如衬线舒服，代码块内不能用行内格式。

## more [A] than anyone had thought [B]

语义：超出所有人的预期上限。A 是被比较的属性，B 是人们原本以为的上限。

```
The launch went more smoothly than anyone had expected.
```

发布比任何人预期的都顺利。最简形态：more 副词 + than anyone had expected。

```
The results were more dramatic than anyone had thought possible.
```

结果比任何人认为可能的都更惊人。

结构拆解（同为代码块，骨架加槽位标注）：

```
比较从句里藏着省略：
  anyone had thought *(it)* possible
                    宾语省略 ↑  宾补
还原平语序：anyone had thought it was possible
已知语法点 think it + 形容词 被塞进了 than 从句
```

变体采集：

```
more than words can express   基准=言语能表达的
harder than it looks          基准=表象
```

## [前项], let alone [后项]

语义：前项尚且达不到，后项更别提。递进否定。

```
He can't even build the project locally, let alone ship it to production.
```

他本地连构建都跑不起来，更别提发布到生产环境了。

```
I barely have time to read email, let alone design docs.
```

我连读邮件的时间都几乎没有，更别提设计文档了。

结构拆解：

```
let alone = 并列连词（同族 not to mention / to say nothing of）
规则：后项平行于前项同位置成分
  build（动词） → ship（动词）
  email（名词）  → design docs（名词）
省略结构：let alone (anyone could) ship (it)
```

常见误读：单独的 leave sb alone 才是"让…独自待着"；句中逗号后的 let alone 几乎总是递进连词。

## not so much [A] as [B]

语义：与其说[A]不如说[B]。书面评论、事故复盘高频。

```
The outage was not so much a technical failure as a process failure.
```

与其说是技术故障，不如说是流程故障。

```
She is not so much shy as careful with words.
```

与其说她腼腆，不如说她措辞谨慎。

结构拆解：

```
A、B 必须同类语法单位（名词对名词、形容词对形容词）
语义重心落在 B 上
肯定版对照：It was as much luck as skill（各占一半）
```
