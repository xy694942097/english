# 框架挖掘方法（2026-09-16 定版）

本文是"从成文语料中挖掘句子框架"的操作规则。历史教训与定版方法都在这里，供后续所有挖掘任务（教材、真题、字幕、原版书）引用。

## 一、历史教训：为什么 regex 挖不出多少

三次实施数据（同一批教材语料）：

| 方法 | 产出 | 教训 |
| --- | --- | --- |
| 课标项目表回忆（2026-09-16 早） | 7 个框架 | 根本不是挖掘，是按预设清单回忆，教材原文都没碰 |
| 预设模式 + regex 两轮扫描 | 20 个框架 | regex 本质是"我认识什么才能找到什么"——只能挖到有固定钩子词的框架（not only、no matter、what if） |
| LLM 逐句通读试点（300 句） | 25 个新框架 + 18 单句候选 | 结构型框架（同位语插入、指示回指、主谓间插入语、承前省略并列）没有任何固定词，regex 永远视而不见 |

结论：**发现框架靠"读"，回收例句靠"搜"**。两件事不能都压给 regex。通读 300 句的产出（非预设、regex 盲区）超过 regex 扫全部 14k 句的产出（预设内）。

## 二、定版流程（四步）

### 第 1 步：建"成文语料池"

通读对象是**所有成文的东西**，不只课文正文：课文、对话、听力原文（Tapescripts 在教材全文里）、真题阅读文章、精翻文本。不是成文的（单词表、短语清单、纯语法讲解）不进池。

入库要求：每个句子带出处元数据（册别/单元/年份/卷别）；PDF 断字先归一化（词典驱动的碎片合并：仅"前片段不是词且拼合是词"才合并，避免把 is used 误合）；噪声过滤（填空残片、指令行、OCR 断字句剔除）。参考实现：references/textbook_mining/ 的 junior_sentences.json（初中 5,588 句）与 pep_sentences.json（高中人教 8,523 句）。

筛选信息句：≥8 词的句子进入通读池（短对话轮次框架密度低），排序后按 300 句一批切分。

### 第 2 步：LLM 逐句通读（发现框架）

每批 300 句派一个子代理通读，规则：

1. **逐句通读，不许抽样跳读**。
2. 一个"框架"必须**至少在 2 个不同句子重复出现**（重复性验证）；单句有趣的句式记为"候选"，不算框架。
3. 每框架输出：frame（[A]/[B] 占位槽位）、gloss（一句话中文语义）、pattern_notes（结构说明）、examples（**逐字复制**原句并带 id 与出处）。禁止发明、改写、拼接例句——宁少报不编造。
4. 产出 JSON 存 references/textbook_mining/llm_batches/（batch_NNN.json 输入 / result_NNN.json 输出）。
5. 子代理自查 + 主会话独立复核：每条例句与原批同 id 的 s 逐字比对（试点 89 例 0 不一致才算通过）。

提示词里附上"已有框架清单"（避免重复发现，但允许报告新变体），并给出 regex 盲区的结构型框架提示清单（同位语、指示回指、插入语、承前省略、名词化串联、时体框架、使役/感官补语等）——提示是举例不是清单，不许只按提示找。

### 第 3 步：合并聚类（跨批去重）

各批产出的框架按骨架相似度合并（"同位语插入"在多批出现即同一框架），同名不同表述的归一。聚类后形成全局框架登记表：框架名、gloss、全部批次中的例句分布。

### 第 4 步：regex 反查（回收例句）

框架确认后，用 regex 在**全语料**反查该框架的完整例句分布——此时 regex 的用途是为已确认框架回收例句与出处，不是发现框架。反查模式按框架定制（结构型框架写不出的，靠通读阶段的例句池）。

## 三、编纂与入库边界

- 挖掘中间物（句子池、批次、聚类结果）存 references/textbook_mining/，可复查可重跑。
- 编纂成章时例句标出处（册别·单元/年份·卷别）；OCR/社区整理版语料的诚实披露照旧（不宣称与官方出版物逐字一致）。
- 单框架章内收录 2-4 个最佳例句，剩余命中留在中间物里备查；不为凑数降低筛选标准。
- 新章走既有管线：number_frame_sections.py / build_chapter_previews.py / build_frames_collection.py（三脚本 CHAPTERS 清单同步加新章，幂等）。
